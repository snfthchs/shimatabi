# シマタビ（仮）

沖縄の小規模な体験事業者と旅行者をつなぐ、体験予約プラットフォームのMVPである。旅行者がスマホで体験を探して予約し、事業者が管理画面で承認する。探す入口として、AIコンシェルジュ（まずはモック）を持つ。

何を作り、何を見送ったかは、[MVPスコープ](docs/product/mvp-scope.md)にある。設計の全体は `docs/product/` と `docs/adr/` にまとめている。

デモの手順は、[デモの手順](#デモの手順)にある。通した結果は、[デモのチェックリスト](docs/demo-checklist.md)に記録している。AIとの開発の振り返りは `docs/ai-dev-log.md`、提出用の設計の要約は [`docs/summary.md`](docs/summary.md) にある。

## 必要なもの
- Python 3.12
- Node.js（npm つき）

## セットアップ
リポジトリ直下で、次を実行する。

```bash
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements-dev.txt
npm --prefix frontend install
```

設定は、`.env.example` を `.env` にコピーして使う。`.env` はコミットしない。空のままの項目は、既定値になる。

```bash
cp .env.example .env
```

予約者の個人情報（氏名・電話・メール）を暗号化する鍵が必要である。次のコマンドで鍵を作り、出力された文字列を、`.env` の `PII_ENCRYPTION_KEY=` のあとに書く。

```bash
backend/.venv/bin/python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

- 鍵がないと、バックエンドは起動しない（起動のときに、原因が分かるエラーになる）。
- 鍵は、コミットしない。鍵をなくすと、暗号化した個人情報は読めなくなる（デモ用のDBは、シードで作り直せる）。
- 鍵は、カンマ区切りで複数書ける。先頭の鍵で暗号化し、すべての鍵で復号を試す（鍵を入れ替えるときに使う）。

## デモ用データの投入（シード）
架空の事業者・体験・便・予約を、DBに入れる。`backend/` で実行する。

```bash
cd backend && .venv/bin/python -m app.seed --reset
```

- `--reset` は、すべてのテーブルを消して作り直してから投入する。`--reset` なしは、空のDBにだけ投入する。
- **デモの直前に `--reset` で作り直す**と、今日の午後の便が受付中の状態になる。今日の便は、実行した時刻より後のものだけを作る。
- 事業者アカウントのログインIDは、`demo-marine`、`demo-craft`、`demo-night`、`demo-food`。パスワードは、架空・デモ専用の固定値で、`backend/app/seed.py` の `DEMO_PASSWORD` にある。
- `.env` の `APP_ENV=production` のときは、シードを実行できない。
- DBのファイルは `backend/data/shimatabi.db` にできる（コミットされない）。

## 起動
ターミナルを2つ開いて、それぞれで起動する。

バックエンド（http://localhost:8000）:

```bash
cd backend && .venv/bin/uvicorn app.main:app --reload --env-file ../.env
```

フロントエンド（http://localhost:5173）:

```bash
npm --prefix frontend run dev
```

画面（http://localhost:5173）が開き、AIコンシェルジュに相談できれば、画面とAPIがつながっている。フロントエンドの開発サーバーが `/api` をバックエンドへ転送するので、画面とAPIは同じオリジンで動く。APIの文書は http://localhost:5173/api/docs で見られる。

## 旅行者の画面
スマホ幅を基本にして、PC幅（1024px以上）にも対応した画面である（レスポンシブ）。PCでは、一覧は複数列、トップと詳細は2カラムになる。ログインは不要。

| パス | 内容 |
|---|---|
| `/` | AIコンシェルジュに、文章で相談する。提案から、体験の詳細へ進む |
| `/experiences` | 体験の一覧。日にち・人数・エリア・種類・子連れOK・雨でもOKで絞る（条件はURLに入る） |
| `/experiences/:id` | 体験の詳細と、予約フォーム（便の選択、人数、氏名・電話・メール）。`?slot=ID` で便を選んだ状態で開く |
| `/bookings/complete` | 予約の完了。予約番号を表示する。予約の直後だけ表示され、再読み込みすると、予約の確認へ誘導する |
| `/bookings/lookup` | 予約番号と、電話またはメールで、予約の状態を確認する |

- APIの型は、バックエンドのOpenAPIから生成して、`frontend/src/api/schema.d.ts` に置いている（手で編集しない）。APIを変えたら、バックエンドの仮想環境を作ったあとで、`npm --prefix frontend run gen:api` を実行して、生成し直す。
- 体験の写真は、仮の画像（`frontend/public/photos/`、自作のイラスト）である。実際の写真は、事業者から提供を受けたものに差し替える想定。
- 氏名・電話・メールは、予約の送信と状態の確認のときだけ送る。URLやブラウザの保存領域には残さない。

## 事業者の画面
PC幅を基本にして、スマホ幅にも対応した画面（最大 `max-w-5xl`）。デモ用のアカウントは、シードの節にある。

| パス | 内容 |
|---|---|
| `/admin/login` | ログインIDとパスワードで、ログインする |
| `/admin/bookings` | 予約の管理。便ごとに予約を並べ、承認待ちの件数と予約を目立たせる。承認と却下は、一覧から直接行う（却下は、確認の操作を挟む）。「承認待ちだけを表示する」で絞れる |

- 未ログインで `/admin/bookings` を開くと、`/admin/login` へ戻る。ログアウトすると、サーバー側のセッションを消し、画面に残ったデータも捨てる。
- 氏名・電話・メールは、伏せ字で表示する。「連絡先を表示」を押したときだけ、その1件の平文を取得し、画面の状態にだけ持つ（URL・ブラウザの保存領域・クエリのキャッシュには残さない）。「連絡先を隠す」で、伏せ字に戻る。
- すでに処理された予約を、承認・却下しようとしたときは、「すでに処理されています」と表示して、一覧を更新する。

## デモの手順
5分程度の流れ。**午後の便が始まる前に**、上の「デモ用データの投入（シード）」の `--reset` で、DBを作り直してから始める（夕方以降に入れると、「今日の午後」の便がなく、最初の質問で提案が出ない）。バックエンドとフロントエンドを、「起動」の節のとおり起動しておく。

1. **旅行者（スマホ幅のほうが見せやすい）**: http://localhost:5173 で、AIコンシェルジュに「今日の午後、那覇から行ける子連れOKの体験ある？」と聞く。提案が、理由つきで出る。
2. 提案の「型染めコースター体験」（承認制）の便を選んで、詳細へ進み、架空の氏名・電話・メールで予約する。「承認待ち」と予約番号が出る。番号は控えておく。
3. **事業者（PC幅のほうが見せやすい）**: http://localhost:5173/admin/login で、`demo-craft`（パスワードは、シードの節のとおり）でログインする。承認待ちの予約が、目立つ表示で見える。
4. 氏名・電話・メールは、伏せ字になっている。「連絡先を表示」を押すと、その1件だけ、全体が見える。
5. 「承認する」を押す。状態が「確定」になる。
6. **旅行者**: 「予約の確認」で、予約番号と、予約のときの電話番号（またはメール）を入れる。「確定」と表示される。連絡先を間違えると、「見つかりませんでした」になる。
7. 満席の便（シードの「青い海のシュノーケルツアー」の、最初の便）は、「満席」で選べない。APIに直接送っても、断られる（409）。
8. ログアウトして、`/admin/bookings` を直接開くと、ログインへ戻る。別の事業者（`demo-night` など）でログインすると、その事業者の予約だけが見える。

（P1）便を中止にして、参加者への連絡文を出す機能は、作っていない。

## 事業者のログイン（API）
| メソッド | パス | 内容 |
|---|---|---|
| POST | `/api/admin/login` | ログインIDとパスワードでログインする。セッションのCookieが設定される |
| POST | `/api/admin/logout` | ログアウトする（サーバー側のセッションを削除し、Cookieを消す） |
| GET | `/api/admin/me` | ログイン中の事業者の情報を返す |

- セッションの有効期限は8時間（固定）。Cookie は `HttpOnly`、`SameSite=Lax`（HTTPSのときは `Secure`）。
- デモ用のアカウントは、シードを投入すると使える（ログインIDとパスワードは、上のシードの節にある）。
- エラーは、すべて `{"error": {"code": "...", "message": "..."}}` の形で返る。

## 体験・予約のAPI
旅行者向け（ログイン不要）:

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/experiences` | 体験の一覧。クエリ: `date`（日本時間の日付）、`party_size`、`kids_ok`、`rain_ok`、`area`、`category`、`max_minutes_from_naha`。条件に合う受付中の便を持つ体験だけを返す |
| GET | `/api/experiences/{id}` | 体験の詳細と、これから始まる受付中の便（満席は残席0で含む） |
| POST | `/api/bookings` | 予約を作る（201）。氏名・電話・メールは、すべて必須。即時確定の体験は確定、承認制の体験は承認待ちになる |
| POST | `/api/bookings/lookup` | 予約番号と連絡先（電話またはメール）で、予約の状態を確認する。連絡先は個人情報なので、URLではなくPOSTの本文で送る |

事業者向け（要ログイン。自社のデータだけ。他社のデータは404）:

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/admin/slots` | 自社の便と、便ごとの予約の状況（承認待ち・確定の人数） |
| GET | `/api/admin/bookings` | 自社の予約の一覧。氏名・電話・メールは、サーバー側でマスクして返す |
| POST | `/api/admin/bookings/{id}/approve` | 承認待ちの予約を承認する |
| POST | `/api/admin/bookings/{id}/reject` | 承認待ちの予約を却下し、押さえていた定員を解放する |
| GET | `/api/admin/bookings/{id}/contact` | 1件の予約の連絡先を、平文で返す（「連絡先を表示」） |

- **定員は、条件付きUPDATEで守る**。承認待ちの予約も、定員に数える。満席・開始後・中止の便への予約は、409（`SLOT_UNAVAILABLE`）。すでに処理した予約の承認・却下は、409（`INVALID_STATE`）。
- 日時のレスポンスは、UTC（`Z` つき）。画面が、日本時間に直して表示する。

## AIコンシェルジュ（API）
| メソッド | パス | 内容 |
|---|---|---|
| POST | `/api/concierge/search` | 本文は `{"message": "…"}`（1〜500文字）。文章から検索条件を取り出し、条件に合う体験を、理由つきで提案する。ログイン不要。予約は実行しない |

例: 「明日の午後、那覇から行ける子連れOKの体験ある？」と送ると、`conditions`（読み取れた条件）、`suggestions`（提案。体験・便・理由）、`reply`（返答の文章）が返る。

- 流れは、①文章から条件を取り出す（AIプロバイダー）→ ②**アプリがDBを検索する** → ③返答文を作る（AIプロバイダー）。**検索と予約は、AIに任せない**ので、提案は、必ずDBにある体験と受付中の便だけになる。理由（子連れ可、那覇からの時間、残席など）は、DBの事実からアプリが作る。
- 条件に合う便がないときは、条件を1つずつ外して再検索し、件数のある緩め方（「雨の条件を外すと1件あります」）を返す。条件が読み取れないときは、一覧へ誘導する文を返す。
- 現在のAIプロバイダーは、**ルールベースのモック**（LLMを使わない）。環境変数 `AI_PROVIDER` は、`mock`（既定）。`llm` は、まだ実装されておらず、指定すると、起動のときにエラーになる。読み取れる言葉は、`backend/app/ai/mock_provider.py` の冒頭にある。
- 旅行者の文章は、**ログに残さず**、応答にも含めない。AIには、文章と現在時刻だけを渡す（予約者の個人情報は渡さない）。
