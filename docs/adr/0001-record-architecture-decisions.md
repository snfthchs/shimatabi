# 0001. 設計判断をADRとして記録する

- ステータス: 承認
- 日付: YYYY-MM-DD

## 背景
AIと一緒に開発していると、「なぜこの設計にしたか」がコードからは読み取れなくなりやすい。理由が残っていないと、AIは前提を知らないまま、過去の判断と矛盾する変更を提案してしまう。人間にとっても、あとで判断を見直すときの材料がない状態になる。

## 決定
設計上の判断は `docs/adr/NNNN-<タイトル>.md` に、`docs/adr/template.md` の形式で記録する。

- 対象: 技術スタック、データ構造、認証方式、外部サービスの選定など、あとで変えにくい判断
- ADRは書き換えない。判断を変えるときは新しいADRを作って、古いADRのステータスを「NNNN で置き換え」にする

## 結果
- AIに設計の前提を渡せるので、判断と矛盾する提案が減る
- 判断のたびに記録の手間がかかる
