# 0007. AIコンシェルジュのLLMにClaudeを使い、AIに渡す前に個人情報を伏せる

- ステータス: 承認
- 日付: 2026-11-23

## 背景
AIコンシェルジュは、ルールベースのモックだけで動いていた（[設計の概要](../product/design-overview.md)の6章）。LLMへの接続は、P1として、差し替え口（`ConciergeProvider`）だけを用意してあった。

LLMをつなぐと、次の2つの心配が出る。

- **個人情報**: 旅行者が打った文章は、外部のAIサービスへ送られる。誤って、電話番号などを書かれても、送らないようにしたい。
- **予算**: 個人の開発で、費用を、前払いの範囲に収めたい。

## 選択肢
| 案 | 良い点 | 悪い点 |
|---|---|---|
| Claude（Anthropic） | 前払い制で、残高を超えて使えず、月額の上限も設定できる。API入出力は、既定で、学習に使われない | 最低の購入額が約5.5ドルで、少額から試しにくい。入出力は30日以内に削除されるが、安全チェックに引っかかると、最大2年保管される |
| OpenAI | 月額の上限を設定できる | 上限が即時には止まらず、少し超過しうる。ゼロ保持は、Enterprise契約が必要 |
| Gemini（Google） | 導入が一番ラクで、無料枠がある | 集計に遅れがあり、超過は自己責任。無料枠は、学習に使われる可能性が高い（要確認） |

## 決定
**Claude（Anthropic）を使う。** 人間が、セキュリティと予算の面で、もっとも良いと判断して選んだ。予算の面では、前払い制で、残高を超えて使えず、月額の上限も設定できる点が大きい。セキュリティの面では、API入出力が、既定で、学習に使われない点を、参考にした（公式のヘルプで確認）。

### 設計の判断
| 項目 | 決めたこと | 理由 |
|---|---|---|
| 切り替え | 環境変数 `AI_PROVIDER` をやめ、`ANTHROPIC_API_KEY` の有無で切り替える（あればLLM、なければモック） | 選べる値が実質1つになり、設定を減らせる |
| モックの扱い | **消さずに、代替として残す**。キーがないときと、LLMが失敗したときに、モックで答える | このリポジトリをクローンした人は、キーを持たない。デモの最中の、残高切れ・月額の上限・回線の不調でも、AI相談を止めない |
| 失敗したあと | 30秒間は、LLMを呼ばずに、モックで答える | 残高切れなどが続くとき、毎回、待ち時間を使わないため |
| モデル | 環境変数 `ANTHROPIC_MODEL`（既定は `claude-haiku-5-5`）。選択肢は、READMEにある | もっとも安く、速い。必要なら、上位のモデルに切り替えられる |
| LLMの担当 | ①条件の抽出、②返答の冒頭の1文、だけ。検索と予約は、LLMに任せない | 幻覚の防止と、費用の抑制 |
| LLMに渡すもの | ①は、旅行者の文章（個人情報を伏せたあと）と、今日の日付。②は、読み取った条件と、見つかった件数。**体験の名前・概要・理由（DBの内容）と、予約者の個人情報は、渡さない** | 外へ出る情報を、最小にする。画面は、返答の最初の行と最後の行だけを使うので、LLMには、冒頭の1文だけを書かせれば足りる |
| LLMの出力 | 条件は、JSONスキーマで受け取り、`Conditions` で検証し直す。形が正しくなければ、失敗として、モックに切り替える。冒頭の1文は、1行・120文字以内。拒否（`refusal`）や、長さ切れも、失敗として扱う | LLMの出力は、信用しない |
| 呼び出しの設定 | 待ち時間20秒、再試行1回、`effort: low`、出力の上限は、条件が512、冒頭の1文が300トークン | デモで、長く待たせない。費用を抑える |

### 個人情報のガード
旅行者の文章は、AIに渡す前に、`app/ai/pii_guard.py` を通す。モックにも、LLMにも、同じ処理を通す（`run_concierge` の中で行う）。

| 種類 | 検知するもの | 置き換え |
|---|---|---|
| メールアドレス | `taro@example.com` | `[メールアドレス]` |
| カード番号 | 13〜19桁の数字の並び（区切りを含む）。検査の数字（Luhn）が合わなくても、一部が残らないように、すべて伏せる | `[カード番号]` |
| 電話番号 | 10〜11桁で、0から始まるもの。`+81` も | `[電話番号]` |
| 郵便番号 | `〒900-0001`、`900-0001` | `[郵便番号]` |
| 12桁の番号 | `1234 5678 9012`（マイナンバーなど） | `[番号]` |

- 見つけたときは、**伏せて、そのまま探す**。応答の `pii_masked` を真にして、画面に、「AIには送らずに、伏せて探しました」と知らせる。提案に、個人情報は要らないので、伏せても、質は下がらない。
- 全角の数字や記号は、半角にそろえてから調べる。
- LLMに「これは個人情報か」を聞くことは、しない。確かめるために、個人情報を外へ送ることになるため。

## 結果
- キーがなくても、AI相談が動く。キーがあれば、LLMで、より自然に答える。LLMが失敗しても、止まらない。
- DBの内容と、予約者の個人情報は、LLMに渡らない。これは、テスト（`tests/test_concierge_pii.py`）で固定している。
- 費用は、Haiku 5.5で、1回の相談（呼び出し2回）が、約0.05円（AIの概算。実際の請求では、未確認）。最低の購入額（約5.5ドル）でも、1万回以上に相当する見込みである。
- **前払いは、返金できず、1年で失効する。** 慎重に使うために、次を勧める。
  - Consoleの「Spend limits」で、月額の上限を、低めに決める（購入額より低くしてよい）。
  - 使わない間は、`.env` の `ANTHROPIC_API_KEY` を空にする（モックで動く）。
  - 使用量を、Consoleの「Usage」で、ときどき見る。
  - 公開のデモにするときは、アプリ側にも、利用回数の上限を設ける（今は、設けていない）。

### 残るリスクと、確認できていないこと
- **氏名と住所は、形が決まっていないので、確実には検知できない。** 画面の注意書きと、ログに残さない作りで補う。旅行者が、氏名や住所を書いたときは、伏せ字にならずに、外部のAIサービスへ送られうる。
- 旅行者の文章（伏せたあと）は、外部のAIサービスへ送られる。サービス側では、標準で30日以内に削除されるが、**自動の安全チェックに引っかかった入出力は、最大2年保管される**。
- Haiku 5.5が、30日の保持が必須の「Covered Models」にあたるかは、確認できていない。
- 日本円で支払えるかは、確認できていない（最低の購入額は、約5.5ドルと、人間が確認した）。クレジットは、1年で失効し、返金できない。
- 実際のAPIでの動作は、人間が確認した。**ただし、LLMが失敗すると、モックで答える作りなので、アプリの画面だけでは、LLMで答えたのか、モックで答えたのか、見分けにくい。** LLMで動いているかは、起動のログ（「AIコンシェルジュ: LLM（モデル: …）」）と、`backend/scripts/check_llm.py`（失敗を隠さずに表示する）で確かめる。起動のログは、キーとモデルの設定を示すだけで、個々のリクエストが成功したかは示さない。失敗したときは、ログに、警告（「LLMでの…に失敗したため、モックで答えます」）が出る。
- 自動の利用回数の上限は、ない。上限は、Consoleの月額の上限と、前払いの残高だけである。
- Haiku 5.5では、拒否（`refusal`）のときに、サーバー側の自動の代替はない。このアプリでは、失敗として扱い、モックで答える。
- 本格運用の前に、データ保持・利用規約・個人情報保護法の面を、見直す。
