# 0005. 画面は、スマホ幅とPC幅の両方に対応する（レスポンシブ）

- ステータス: 承認
- 日付: 2026-11-23

## 背景
設計では、旅行者の画面はスマホ幅、事業者の画面はPC幅を基本にした（`docs/product/design-overview.md` の5章）。短い時間で作るため、旅行者の画面は、スマホ幅の1列（`max-w-md`）に固定した。このため、PCで開くと、画面の中央に細く表示される。事業者の画面も、スマホ幅での確認はしていなかった。

探す操作はスマホでもPCでも行われ、事業者が、外出先のスマホで予約を確認することも考えられる。どちらの画面も、どちらの幅でも使えるようにしたい。

## 選択肢
| 案 | 良い点 | 悪い点 |
|---|---|---|
| A. 今のまま（旅行者はスマホ幅に固定、事業者はPC幅） | 作業が要らない | PCで旅行者の画面が細く、事業者の画面をスマホで使いにくい |
| B. 1つのコードで、画面の幅に応じてレイアウトを変える（レスポンシブ。境目は `lg:` の1つ） | コードが1つで済む。スマホ向けの今の操作を、そのまま保てる | PC幅用のレイアウトを、画面ごとに足す必要がある |
| C. スマホ用とPC用の画面を、別々に作る | 画面ごとに、最適な見た目にできる | 画面とルートが倍になり、直すときも倍かかる |

## 決定
Bを選ぶ。理由は次のとおり。
- すでに使っているTailwind CSSの、幅に応じた指定（`lg:` など）だけで足りる。部品やルートを増やさずに済む。
- 境目は、`lg:`（1024px）の1つに絞る。事業者の画面が、すでに `lg:` を使っているので揃えられる。タブレット幅（768px）は、スマホと同じ縦積みにして、確認する幅と、直す箇所を減らす。
- スマホ幅は、今の見た目と操作（予約のボタンを画面の下に固定するなど）を保つ。

| 画面 | スマホ幅（1024px未満） | PC幅（1024px以上） |
|---|---|---|
| 共通の枠 | 全幅の1列 | 中央の枠（最大 `max-w-5xl`）。ヘッダーとナビを横に並べる |
| トップ | 縦1列 | 左に入力と条件、右に結果 |
| 体験の一覧 | 1列（640px以上は2列） | 左に絞り込み、右に2列のカード |
| 体験の詳細・予約 | 縦1列 | 左に写真と説明、右に予約のフォーム |
| 予約の完了・確認 | 縦1列 | 読みやすい幅（`max-w-xl`）で中央に表示 |

## 結果
- PCで開いても、画面が細くならない。事業者の画面も、スマホ幅で使える。
- 画面を変えたときは、スマホ幅とPC幅の両方で確認が要る。フロントエンドの自動テストは作らない方針なので、確認は、ブラウザでの手動で行う（`docs/demo-checklist.md`）。
- 見た目の作り込み（色・写真・文言）は、この決定の対象外とする。
